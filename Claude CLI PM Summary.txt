What's built

- App: a Next.js static export served by FastAPI at /, all in one Docker container. It runs on port 8000 (or PORT), with start and stop scripts for Mac, Linux and PC.
- Sign-in: a hardcoded user / password, enforced by the backend. Sesase, sent in an HTTP-only cookie and don't expire.
- Database: SQLite through the built-in sqlite3 module, stored on the pm_data volume. It has five tables: users, sessions, boards, board_columns and cards. The schema
  supports multiple users, with one board per user.
- Board: the API reads and writes the whole board as one JSON document, and each write replaces all the cards in one transaction. Column set and order are fixed, and
  only titles can change. Cards can be added, edited, deleted and dre a reload or container restart.
- AI chat: POST /api/chat calls openai/gpt-oss-120b through OpenRouter and gets back a reply plus either the complete updated board or null.
  - Invalid responses: these return 502 and leave the board unchange
  - Excluded providers: CoreWeave truncated boards and DeepInfra ignored the schema in measured responses, so both are excluded.
  - Chat history: it stays in the browser and is cleared by a reload
- Tests:
  - Backend: pytest runs in Docker, with live model tests kept out o
  - Frontend unit: vitest with a mocked API.
  - Browser: Playwright runs against a separate container on port 80ocks the chat route.

Known limitations

- Dropped cards: if the AI drops a card from an otherwise valid resped deletion, so the card is deleted. This wasn't seen in testing.
- Overwritten changes: the last write wins, so an AI update can overwrite changes you make while it's working on a reply.
